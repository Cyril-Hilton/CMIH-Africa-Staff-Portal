# Payslip download and logo correction

The portal's Download Payslip link opened an HTML statement. Its internal Download / View Payslip button pointed back to another HTML statement, rather than returning a PDF attachment. The HTML logo depended on a separate asset URL, and screen dark-mode styles could override print presentation.

Added a server-rendered A4 PDF download from the existing issued Payslip snapshot, using the same recipient and signed-access authorization as the HTML statement. Both download buttons now request the PDF explicitly. The PDF contains an embedded company logo and uses the recorded monthly salary/deduction/banking values, without recalculating from the employee's current payroll setup. HTML preview and browser print also use embedded logos; screen dark mode is restricted to screen media, with legible printed table headings.

Synthetic PDF rendered as one A4 page. Poppler rendering was visually checked: company logo, office letterhead, employee metadata, all earnings/deductions, net salary and footer are present and legible. Tests cover the actual PDF content type and attachment filename, image embedding, the HTML download link, employee ownership, signed-link expiry and tamper rejection. No payroll data is regenerated by downloading.

The requested employee account was verified in production. August and September 2026 issued statements exist; October has no issued record in that account. A connected-mail search did not locate an existing October copy. An October statement must not be fabricated using current salary figures. The user's one-off email request does not re-enable automated portal emails.
